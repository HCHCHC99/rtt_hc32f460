# 任务栈剩余固定为 75 字节故障记录

> 记录日期：2026-08-27
> 状态：**现象已实测复现；原因未分析、未修复**

## 一、当前告警

RTT 实际输出：

```text
[MAIN] [TASK_STACK] WARN led sp=0x1FFFF09C base=0x1FFFE954 size=2048 used=1973(96%)
```

按该输出计算，LED 线程栈剩余：

```text
2048 - 1973 = 75 字节
```

## 二、修改 TASK_STACK_LED 的实测现象

现场原始记录：分别尝试修改 `TASK_STACK_LED` 为 `1024 / 2048 / 4096`，现象表现为“剩余的 stack 都是刚好只剩下 75”。当时同时给出的数字是：

```text
949、4021、8117
```

注意：这组数字与三项配置值的对应关系或统计口径未在原始记录中写清；但当前日志已经明确给出 `size=2048 used=1973`，可直接推出本轮剩余为 `75` 字节。

## 三、调换任务启动顺序后的现象

将 `Di_Task_Start()` 和 `Led_Task_Start()` 调换位置后，先启动 DI 任务时，同样的“剩余 75”现象会出现在 **DI 任务** 上，而不是 LED 任务。

因此该现象不是只在 LED 业务代码中稳定出现的单任务问题。

## 四、当前配置下的内存观测

当前告警线程栈参数：

```text
base = 0x1FFFE954
size = 2048
sp   = 0x1FFFF09C
used = 1973
```

调试器 Memory 窗口观测：

| 地址 | 观测值 | 说明 |
|---|---|---|
| `0x1FFFE954` | `23232323` | 栈基址附近是哨兵数据 |
| `0x1FFFE954 + 75` | `23232301` | 从此处开始出现非 `'#'` 数据 |
| `0x1FFFE954 + 2048 - 204` | `23232323` | 该地址仍是哨兵数据 |
| `0x1FFFE954 + 2048 - 128` | `49470000` | 该地址已不是哨兵数据 |

其中第一行告警给出的“剩余量”就是 `75` 字节。
