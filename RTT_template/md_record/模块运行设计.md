# 模块运行设计（RTOS 下设备 update 的执行模型）

> 记录日期：2026-08-25
> 状态：设计定稿；**registry 升级（B+C 混合）待实施**，A 模式（电源链 ISR）已实施

---

## 一、背景：从裸机 1ms 主循环到 RTOS

**工况**：推杆（线性执行器）控制器，5 个模块：

| # | 模块 | 裸机下怎么跑 |
|---|---|---|
| 1 | 电源极性 | GPIO 读取 + 10ms 窗口，判定正/反向（正向伸出、反向缩回） |
| 2 | 上下霍尔限位 | GPIO 读取 + 10ms 窗口，判定到上限/下限 |
| 3 | 电机控制 | 被动设备，开放回调整合多源输入 → 输出伸/停/缩 |
| 4 | 通讯 | 输入=客户指令；输出=回令/状态（状态由其他设备事件修改） |
| 5 | 电机霍尔 | 测转速/转向，实时更新 |

**核心认知**：RTOS 下**不是把 1ms 主循环原样搬成 task**，而是按"谁产生 / 谁消费 / 怎么通知"重新分工：
- 生产者：中断 / 采集任务 / 通讯解析；
- 消费者：控制/仲裁线程（被动等）；
- 通道：事件位（状态跳变）/ 队列·邮箱（带数据）/ 信号量（计数）/ 共享状态（持续值）。

**RTOS 的优先级解决"同时就绪谁先跑"，不是"轮询顺序"**；裸机轮询顺序被拆成：优先级（抢占）+ 周期（timer）+ 阻塞（事件/队列）。

## 二、三种执行模型

| 模型 | 做法 | 适合 | 代价 |
|---|---|---|---|
| **A ISR 驱动** | 定时器/外设中断里做最轻的 update（采样/标志/事件），重活丢线程 | 高频、硬实时、抖动敏感（采样/保护） | ISR 要短，不能阻塞 |
| **B 协作周期** | 共享 dev 线程每 1ms 遍历注册表，按 period 调各设备 task（`Dev_Registry_UpdateAll`） | 中频、非硬实时、数字输入消抖、设备多而杂 | 单设备耗时拖累整表；本质仍是"轮询" |
| **C 独立线程** | 每设备一个线程 + 信号量/事件/队列，`rt_sem_take/rt_event_recv` 阻塞等活 | 阻塞 IO（通讯）、事件驱动逻辑（仲裁/状态机） | 每线程一份栈 RAM；需处理优先级/互斥 |

> 一个系统可三种混用（参考 HB_chuchai：1ms 心跳 ISR 跑 ADC 均值+过流检测 = A；主循环 DeviceManager_UpdateAll = B）。

## 三、推杆 5 模块归宿

| 模块 | 本质 | 归宿 | RTOS 原语 |
|---|---|---|---|
| 电源极性 | 数字输入 + 10ms 消抖 | **B**（共享 DI 采集任务，10ms 周期） | `rt_pin_read` + 跳变事件 |
| 上下霍尔限位 | 数字输入 + 10ms 消抖（安全相关） | **B**（同上，共用 DI 任务） | 同上 |
| 电机控制/仲裁 | 被动仲裁，整合多源输入 | **C**（事件线程，`rt_event_recv` 阻塞；或并入现有 sys_sm） | `rt_event` + 表驱动 |
| 通讯 | 阻塞收发 + 协议解析（输入+输出） | **C**（独立线程） | 队列/邮箱 + 信号量 + 事件 |
| 电机霍尔 | 高频测速/测向 | **A**（ISR 捕获 + 原子共享状态） | TMR/EXTI + `Utils\us_timer` 时间戳 |

**DI 消抖说明**：任务周期 10ms + 连续 N 次一致 = N×10ms 消抖；"10ms 窗口"与任务周期解耦，改 N 即可调。

## 四、registry 升级设计（B + C 混合）【待实施】

把 `SysModule_t` 从"纯周期任务表"升级为"模块执行模型表"：

```c
typedef struct {
    const char *name;
    void (*init)(void);

    /* B 模式：协作式周期任务（共享 dev 线程按 period 调用） */
    void    (*task)(void);
    uint16_t period_ms;

    /* C 模式：独立线程入口（注册时由 registry 创建并启动线程） */
    void    (*thread_entry)(void *param);
    uint16_t thread_stack;     /* 线程栈大小（字节） */

    uint8_t  prio;             /* B=模块优先级(排序参考)；C=线程优先级 */
    uint32_t last_tick;
    uint8_t  enabled;
} SysModule_t;

#define SYS_MODULE_REGISTER(_name, _init, _task, _prio, _period) \
    { #_name, _init, _task, _period, RT_NULL, 0, _prio, 0, 1 }

#define SYS_MODULE_REGISTER_THREAD(_name, _init, _thread, _prio, _stack) \
    { #_name, _init, RT_NULL, 0, _thread, _stack, _prio, 0, 1 }
```

`Dev_Registry_Add` 分发（查重/复制/init 同现有）：

```c
    if (module->init) module->init();              /* 注册即 init，两种模式一样 */
    if (module->thread_entry != RT_NULL) {         /* C 模式：注册时建线程 */
        rt_thread_t t = rt_thread_create(module->name, module->thread_entry, RT_NULL,
                                         module->thread_stack, module->prio, 10);
        if (t) rt_thread_startup(t);
    }
    /* B 模式：task != NULL，等 dev 线程 UpdateAll 按 period 调 */
```

- `Dev_Registry_UpdateAll` **不变**（`if (m->task == RT_NULL) continue;`，C 模式自然跳过）；
- dev 线程（`Dev_Start`）：有 B 模块才启；全是 C 模块可不启；
- 注册示例：

```c
SYS_MODULE_REGISTER("di",  Di_Init, Di_Task, 18, 10);                 /* B：DI 消抖 10ms */
SYS_MODULE_REGISTER_THREAD("comm", Comm_Init, Comm_Thread, 12, 2048); /* C：通讯阻塞线程 */
SYS_MODULE_REGISTER_THREAD("act0", Act0_Init, Act0_Thread, 8, 1024);  /* C：轴仲裁事件线程 */
SYS_MODULE_REGISTER("cur", CurrentSensor_Init, RT_NULL, 3, 0);        /* ISR 驱动：仅 init */
SYS_MODULE_REGISTER("vm",  BusVoltage_Init,    RT_NULL, 3, 0);
```

## 五、事件设计要点（易踩坑）

1. **事件位 ≠ 状态 ≠ 数据**：持续状态→共享变量/事件组 bit；瞬时跳变→`rt_event` 发一次；带数据→队列/邮箱；
2. **只发"跳变沿"**：消抖后 `状态 != 旧状态` 才发，避免每周期刷事件；
3. **rt_event 不计数**：同事件连发多次只算一次；需要计数用信号量；
4. **单一消费者**：一个事件位最好只有一个任务消费，避免抢事件/清 bit 错乱；
5. **共享变量**：volatile + 短临界区（关中断/互斥），或生产者写消费者读单向（环形缓冲）；
6. **事件 + 超时兜底**：`rt_event_recv(..., timeout=10ms)` 事件驱动为主、周期兜底刷慢变量，实战常用。
